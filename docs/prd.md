# PRD — Product Requirements Document

Um **PRD** é um documento que explica o que será construído, por que será construído e como saberemos que ficou pronto.

Para esta trilha, o PRD será simples e direto.

## Funcionalidade documentada

Exemplo:

```text
Cadastrar termo técnico no Glossário Tech para TPM
```

## Objetivo

Explique o objetivo da funcionalidade.

Exemplo:

```text
Permitir que a usuária cadastre um novo termo técnico para estudar depois.
```

## Problema

Explique qual problema essa funcionalidade resolve.

Exemplo:

```text
Durante conversas técnicas, a TPM encontra termos que ainda não entende bem e precisa registrar esses termos em um lugar organizado.
```

## Escopo

Explique o que entra e o que não entra.

### Dentro do escopo

- cadastrar termo;
- informar categoria;
- escrever explicação simples;
- escrever exemplo;
- marcar status como `estudando` ou `entendido`.

### Fora do escopo

- login de usuário;
- múltiplos usuários;
- busca avançada;
- anexos.

## Requisitos funcionais

- A aplicação deve permitir cadastrar um termo.
- A aplicação deve permitir listar termos.
- A aplicação deve permitir editar um termo.
- A aplicação deve permitir remover um termo.
- A aplicação deve permitir marcar o status como `estudando` ou `entendido`.

## Critérios de aceite

- [ ] Consigo cadastrar um termo com todos os campos obrigatórios.
- [ ] Consigo listar os termos cadastrados.
- [ ] Consigo editar um termo existente.
- [ ] Consigo remover um termo.
- [ ] Consigo explicar com minhas palavras o que foi definido no PRD.

## Uso da IA

Você pode pedir ajuda para a IA revisar clareza, encontrar lacunas e sugerir critérios de aceite.

Mas a decisão final é sua: você precisa entender e conseguir explicar cada item.
